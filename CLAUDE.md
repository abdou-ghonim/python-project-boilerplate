# Working in this codebase

## Shape

- `app/api/*` is HTTP only: parse the request, call a service, return JSON.
  Business logic goes in `app/services/*` so a CLI command or a background job
  can reach it without a request.
- The project is database first. `sql/<provider>/*.sql` is the schema; nothing
  creates a table from a Python model. A schema change is a new .sql file in
  every dialect directory, applied with `flask db-apply`.
- `app/models/models.py` is generated by `flask generate-models` and rewritten
  in full each time. Hand-written models go in `extended_models.py`, where they
  mirror the DDL rather than define it — change one, change the other.
- The account model (`app/models/user.py`) maps onto whatever user table the
  configuration names. Read a field through the attribute (`user.role`), never
  through a column name, and check `__mapped_fields__` before writing to one
  that the table may not have.
- Anything that differs between databases belongs in `app/database.py`, and
  anything that differs between login methods in `app/auth/`. Code outside
  those two should not branch on `DB_PROVIDER` or `AUTH_PROVIDER`.
- There is no `utils` package, deliberately. A new module goes next to the
  thing it serves and is named for what it is: everything Redis does is in
  `app/redis.py`, the request id lives with the logging it exists for.
- Redis, rate limiting, caching and background jobs each have an `*_ENABLED`
  switch. A feature that is off must be a no-op at every call site, not an
  error — half a flag is worse than none.

## Conventions

- Configuration is read once, in `config.py`, from the environment. Do not call
  `os.getenv` elsewhere.
- A check that protects against an invisible failure (a weak key, an
  unencrypted connection, a disabled security control) is fatal at startup, not
  a warning.
- Comments explain *why*, especially where the code looks odd — a non-obvious
  default, a driver quirk, a deliberate trade-off. Do not narrate what the code
  already says.
- API errors are JSON with `error`, `status` and `request_id`. Raise `ValueError`
  from a service for a 400, `AuthError` for a 401/403.
- New dependencies: core ones in `requirements.txt`, provider-specific ones in
  `requirements/<provider>.txt`.

## Before claiming something works

```bash
scripts/test.sh
flask db-check
```

Do not add a `routes` command: Flask has one, and its CLI group resolves the
name first, so yours would never run.

A schema change is not done until `sql/sqlite/`, `sql/postgresql/`,
`sql/mysql/` and `sql/mssql/` all have it. Only the SQLite one is covered by
tests; "Verifying a dialect" in `sql/README.md` is the container recipe for
checking the other three, and none of them has been run against a real server
yet.
